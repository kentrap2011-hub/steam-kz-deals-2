## Проблема
Пользователь неоднократно установил operational правило: **рабочий чат автоматически освобождает свой номер после сдачи итогового результата**. Необъединённый implementation PR, внешняя QA или ожидание директорской приёмки НЕ занимают номер завершившего работу исполнителя. Зарегистрированная, но ещё НЕ отправленная пользователем задача резервирует номер и помечается «ожидает запуска», не означает физическую работу. Новая беседа занята лишь после подтверждения пользователем запуска; затем освобождается по итоговому результату, без дополнительного запроса о закрытии окна чата.

Директор продолжает отвечать «физическая доступность неизвестна» даже после сданных отчётов. При этом текущий DIRECTOR_PROTOCOL.md буквально требует UNKNOWN без отдельного user confirmation даже при complete/report. Это вероятное **противоречие канонических правил с многократно выраженной волей пользователя**, а не недостаток внимательности модели. Не выдавать отсутствие доступа к UI ChatGPT за невозможность определить **операционную доступность слота**.
