## Конкретная причина

Независимый ЧАТ 2 проверил PR #274 на точной версии `7d1167ae4201c712fcdcf18330d55c3be5889fb1` и зафиксировал в отдельном отчёте PR #279 (HEAD `e0dcb481b06f549915c03876b54e8735473005c7`) один доказанный дефект:

- В `scripts/taste_steam_review_dossier_buffered.py::_drain_notes_v2_individual` для действительного разрешённого вызова (`offline_fixture=False`) требуется `source.active=true` и `source.authorized_for_canonical_ingest=true`, наряду с отдельными разрешениями писателя.
- Затем `individual_final_readiness` вызывает `dossier_research_notes_v2.py::_manifest` / `_contract`, где безусловно проверяется **обратное**: `active=false`, `authorized_for_canonical_ingest=false`.
- Таким образом разрешённый режим логически никогда не может пройти до сохранения. Старые тесты использовали только `offline_fixture=True` и не выявили ошибку.

Пользователь разрешил точечное исправление; НЕ надо снова анализировать весь Dossier, переделывать механизм писателя или заказывать новые уровни проверки. Нужен один исправленный PR.
