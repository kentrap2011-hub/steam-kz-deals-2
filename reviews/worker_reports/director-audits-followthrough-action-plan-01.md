## Один порядок действий

1. **P0 — сейчас, поведение директора, без PR.** На пяти следующих релевантных запросах сначала классифицировать `STATUS / DECIDE / REGISTER / MERGE`. Читать точную текущую Board/registry запись, report и live PR/CI только насколько нужно; остановиться, когда ответ доказан. Не делать patch/source/log audit ради короткого статуса, не начинать регистрацию незапрошенной задачи. Отмечать число fetch и превышение scope, не утверждать историческую экономию времени. **Приёмка:** 5 случаев без full Board/registry и без самовольного worker-level review, при сохранении всех safety gates.
2. **P1 — первое и единственное предлагаемое новое поручение: `IMPLEMENT` компактного decision/read path.** **Причина:** даже при P0 в тексте остаётся подтверждённая неоднозначность общего gate. **Точный scope:** только `DIRECTOR_PROTOCOL.md` (§1 общий decision gate и §2/§8 короткая передача результата), не изменять смысл existing authority/independent QA/merge. Явные режимы и stop-conditions для `STATUS / DECIDE / REGISTER / MERGE`, локатор точной registry записи и текущего заголовка Board, запрет full historical reads без записанного evidence gap. `REGISTER` сохраняет личную обязанность директора создать named task + JSON + Board и дождаться exact-HEAD CI/merge **до** запуска worker. **Приёмка:** четыре сценария ниже, отсутствие противоречий с START/handoff/preflight; PR только draft, затем независимый `QA` на финальный HEAD. **Зависимость:** отдельная регистрация/разрешение директором; ЧАТ 6 не создаёт этот task.
3. **P2 — отдельный `QA` после P1**, не тот же автор. Проверить exact diff, отсутствие обхода required checks и authority, 4 сценария ниже; `PASS_FOR_DIRECTOR_MERGE_REVIEW` позволяет лишь дальнейшее решение директора, не автоматический merge. Если новый текст не улучшил повторяемое поведение, **только тогда** оценивать Stage B: узкий derived current-view без нового ledger, изменений schema/валидаторов, исторического удаления, CI или production coupling. **Никакой немедленной архивизации 280-КБ Board или 93-КБ registry.**

**Готовое описание ОДНОЙ следующей задачи для директора:** `DIRECTOR_TYPED_DECISION_FASTPATH_IMPLEMENT_01` — новый независимый worker `IMPLEMENT`, после явной регистрации в `main`, с правом менять только `DIRECTOR_PROTOCOL.md`. Ввести четыре типизированных маршрута обращения и строгие stop-conditions; сохранить fresh task/Board/registry/PR/QA/CI/authorization gates и физическую идентичность чатов; запретить второй реестр, генератор, сокращение/архивацию истории, code/runtime/workflow/production changes. Обязательные результаты: маленький diff, таблица четырёх сценариев, worker-report, draft PR и независимый QA exact HEAD. Директор сначала проверяет отсутствие уже активной дублирующей задачи.

## Четыре сценария приёмки без ослабления безопасности

| Команда | Минимальные точные чтения и ответ | Stop-condition / запрет |
| --- | --- | --- |
| **«Проверь чат N»** | Текущий slot→task из актуальных Board/registry, 1 report, live PR `head/state`, релевантный CI при выводе о готовности | Ответить `submitted / in QA / blocked / unknown`; без patch, истории и новой задачи. Если реальный ход чата не виден, не приписывать ему зависание |
| **«Что дальше?»** | Верх Board, только релевантные registry IDs, зависимости, live PR/report при споре | Назвать один приоритет и actor; не делать worker-проверку и не стартовать незапрошенную работу |
| **«Назначь задачу»** | Проверить duplicate, авторизацию/зависимости и слот; затем named task + registry + top Board, exact-HEAD CI и merge регистрации в main | До accepted registration — `BLOCKED_AUTHORITY`, никакого преждевременного worker-handoff; не перекладывать governance-оформление на worker |
| **«Принимай PR»** | Живой PR HEAD, scope, независимый QA на **этот** HEAD, требуемые CI, approval/permission gates | Недоказанный gate → fail closed без merge; не заменять QA зелёным CI и не запускать Deploy/семантику |

**Architecture preflight:** owner canonical state — GitHub; директор — orchestration, worker — bounded implementation/QA. Предлагаемый P1 меняет только процесс чтения, **не** GitHub control-plane, workflow, scope, queue, retry, schedule, semantic execution или production acceptance. Для P2 Stage B потребуется отдельный authorization/preflight. **ЧАТ 6 ничего не изменял**, кроме этого одного отчёта; PR #248 остаётся draft, PR #241 принят. Реальные внутренние причины поведения и время отдельных tool calls недоказуемы по доступным артефактам.
