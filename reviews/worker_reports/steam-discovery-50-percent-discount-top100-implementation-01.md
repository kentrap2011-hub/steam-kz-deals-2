### Implementation and source boundaries

1. Existing `steam_partial_publish_runner.py` continues owning all paid collection. Source traversal now uses ONLY the complete live KZ capped `category1=998` game/Sub sale results, not global DLC `category1=21` or broad `category1=996`. `config/mailing_policy.json#paid_discovery` and `steam_production.py` reflect the exact scope; parsed-row >=50% and >0, <=4500 KZT gates remain mandatory, even if Steam ignores source-side discount filters.
2. The early obscure filter is conservative and deterministic: only observed numeric low-signal Steam Search review rows are rejected (under 50 reviews); exceptional quality (at least 10 reviews/95% positive) or exceptional commercial terms (>=90% off and <=1000 KZT) escape. Missing or untrusted Search review evidence is never treated as confirmed obscurity. Existing stronger review/rating conditions still determine core game eligibility.
3. **DLC:** `steam_targeted_paid_lanes.py` uses the ordinary existing quality/refined shortlist to identify **all** eligible base appids BEFORE any DLC discovery. It calls live `/api/appdetails?cc=kz` once per admitted parent for exact `dlc` identities, and only those appids for current KZT DLC type, price >0 <=4500, discount >=50, and consistent reported parent identity. The target list is never restricted to the visible top 100. Exact App_ identity dedupe applies. Parent/DLC lookup errors fail closed without publishing a falsely complete source. No owned-library shortcut; ownership expansion remains a separate task. These DLC carry no invented review score: their eligibility is conditional on a quality-approved base and their own paid-offer gate, while the existing semantic system remains responsible for final personal relevance.
4. **Packages:** `Sub_` identities found in the games sale response are now admitted as independent discounted purchase candidates without pretending a package has app reviews. The existing fixed-package StoreBrowse producer also reads current discounted `Sub_` rows, even when none of their member apps is on standalone sale. It verifies exact package identity, >=50%, <=4500 KZT and at least two verified included appids before expensive content/standalone route resolution. Unreviewed/non-sold members are listed as requiring independent personal semantic assessment, **never automatically counted as suitable or valuable**. `package_without_candidate_base` now remains an independent multi-game semantic candidate rather than falsely requiring ownership of an external base game.
5. A normal StoreBrowse refresh with moved discount below 50% or price above 4500 KZT now excludes the stale paid offer before family/visual projection. The existing standalone and fixed-package score rules remain the final price/ranking authority.
6. **Deep work + rolling top-100** from the first pass remain: new independent GitHub-owned ordering file; never analyzed first, then historical-oldest completion, and within never analyzed strict deterministic purchase value, Steam percent, review count and stable ID. Sale expiry is not used; no hard 100 before Deep. Final visual producer computes full canonical ranking/stage priority and full Deep processing status, then slices only paid `items` to 100. Positive authoritative current Deep outranks provisional/unanalyzed via the existing Deep-first ranking model.
7. **Funnel:** publisher manifest now includes per-source games/Sub totals, price/discount/extras/software/obscure removals, admitted base count, exact DLC identity and paid accepts/rejects, independent package seen/cheap survivors/admitted, shortlist counts. Source-bound final producer also includes current family-resolved counts and package-content resolution counts when the bound artifacts are present. Reconciliation checks reject incompatible counts/source timestamps. Statistics displays the useful live subset plus full-ranked/visible/hidden counts. Giveaway sibling and ITAD provider paths are unchanged.
