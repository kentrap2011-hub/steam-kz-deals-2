## 4. Exact ordering problem found in the current prompt

The pre-change prompt already said that Russian retrieval was source-agnostic and already required materially different player-feedback surfaces after a failed first surface. However, it also contained a comparatively detailed exact-app Steam recovery path after Russian existence proof.

That combination left a practical ordering ambiguity: a worker could keep trying Store/Community/query/locale variants before giving a generic non-Steam discovery query enough priority. The previous MO:Astray production attempt demonstrated that this ambiguity could consume the full 8-query ceiling before reaching a cheap usable public non-Steam item.

The fix therefore changes retrieval priority, not admissibility.

## 5. Repo-owned implementation

PR #65 implemented the smallest canonical change.

### Worker prompt

`config/taste_steam_review_dossier_worker_prompt.md` now defines an explicit early source ordering after reliable exact-product Russian existence is established:

1. take a cheap safe exact-product Steam item-level success when it is already exposed or immediately reachable;
2. treat these as semantic stop-shapes for continued equivalent Steam priority:
   - aggregate/count-only;
   - inaccessible language-filter representation;
   - profile-scoped item only;
   - concrete Steam cards that are non-Russian;
   - collection/index row without a concrete child;
3. after such a stop-shape, prioritize generic non-site-constrained cross-source discovery;
4. use site-specific follow-up only after ordinary discovery makes that source promising;
5. allow a genuinely new/non-equivalent Steam path later when promising, but do not let equivalent Steam retries postpone the early cross-source pivot.

There is deliberately no fixed number of Steam queries/pages. The pivot is semantic.

## 6. Before/after retrieval flow in plain language

**Before:** Russian existence proven -> keep trying a detailed Steam recovery family -> eventually diversify if the remaining budget permits.

**After:** Russian existence proven -> use a cheap Steam concrete item if it is readily available -> if Steam exposes only an unusable stop-shape, immediately give generic cross-source player-feedback discovery priority -> follow the promising source -> apply the existing stable/fallback evidence rules unchanged.

The new order does not mean “leave Steam after one failure.” If a usable concrete Russian/mixed Steam item is already cheaply reachable, Steam remains the preferred path.

## 21. Efficiency / reusable lesson

Once exact-product Russian existence is already proven, the efficient bounded order is not to exhaust every possible Steam representation. Keep the cheap exact-product Steam success path first, but use semantic stop-shapes to hand priority to one generic cross-source player-feedback discovery query early. A promising result can then receive site-specific follow-up. This preserves exact identity and evidence quality while spending the existing 8/16 budget on genuinely different retrieval opportunities rather than equivalent route variants.
