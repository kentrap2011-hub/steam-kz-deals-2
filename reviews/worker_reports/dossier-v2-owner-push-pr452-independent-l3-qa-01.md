## Reassessment and risk model

Initial L3 reported HIGH because `_owner_push_candidate_gate` authenticates **one** candidate's owner GitHub push but `run_authorized` calls `ingest_local`, which scans all submitted immutable candidates; a different actor's earlier candidate could be receipted by a subsequent owner's valid event. This **is a true limitation in strict per-candidate actor provenance**, not a proven exploit of this project.

The user explicitly clarifies **no other person enters or changes GitHub**, with owner-authenticated ChatGPT connector writes and GitHub-owned trusted Actions as normal writers. Against this actual operating model, the hypothetical non-owner branch writer is out of scope; raising it to a release-blocking HIGH without proving such a writer's access was disproportionate. No extra per-candidate owner event registry or permission redesign is warranted for this six-game run. If a third-party writer or outside automation later receives write access, re-open the actor-provenance requirement before extending this route.

The same broad `ingest_local` sweep serves a practical **recovery purpose** in the user's scenario: when multiple owner `create_file` submissions trigger GitHub Actions concurrently, the last workflow that starts after the final relevant push reads the **current** remote sandbox HEAD, not only the triggering event's immutable snapshot. That run can receipt all submitted, as-yet-unreceipted valid candidates. Earlier receipts are skipped, and each remaining candidate is independently classified and verified.

## Six-file and concurrency review

1. **Input ordering & one-add:** Research launcher creates exactly one GitHub `create_file` per frozen AppID path on the new `sandbox/dossier-notes-v2-fresh6-20261114-rerun1`. `scripts/dossier_notes_v2_research_receipt_ingest.py::_owner_push_candidate_gate` checks actual GitHub `push` event, owner ID 315790060, first attempt, exact branch/sha/event parent, one added path, original frozen assignment, first-parent lineage, no subsequent path edits. Subsequent `run_authorized` authenticates exact owner-issued cohort and GitHub Actions run.
2. **Queue semantics:** auto workflow `.github/workflows/ingest-dossier-notes-v2-research-on-owner-push.yml` uses one concurrency group and `cancel-in-progress: false`. Default GitHub Actions behavior can replace a waiting/pending run with a later one; this does **not** terminate the active run. GitHub official source: https://docs.github.com/en/actions/concepts/workflows-and-actions/concurrency . Newer optional `queue: max` exists but is not required for this bounded six-item **state-based sweep**, and adding it would cause redundant full-cohort validation for each event.
3. **Six files arrive before processing:** `ingest_local` loops over **all six** frozen manifest rows and creates an independently typed receipt for each previously missing valid candidate.
