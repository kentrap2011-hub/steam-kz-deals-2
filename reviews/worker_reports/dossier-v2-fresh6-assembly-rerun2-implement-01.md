## Bounded design choice

A new ordinary GitHub cohort exists in current code, but its Research stage cannot directly reuse old Git introduction SHAs because the cohort's marker/assignment/manifest and first-parent ancestry are different. Rather than weaken that provenance, this implementation adds one owner-authenticated, GitHub-only **deterministic Research content copy**. It creates six fresh **one-add Research candidate+typed receipt** pairs in the new sandbox from the six verified original Research notes, with only the `assignment` rebound to the NEW owner-frozen manifest. No external semantic Research is repeated. The already ready 49520 and 499180 Assembly candidates are preserved unchanged in the old sandbox, but this route explicitly permits a **full six-item new Assembly attempt** under one coherent new trial, not a fake carry-forward acceptance. It does not rewrite old terminal Assembly outcomes or silently narrow the user's six-game request to four.

The user asked to make the six games launchable, not to perform Assembly now. Once source is merged and the real owner run has succeeded, use the dedicated full launcher `config/dossier_notes_v2_fresh6_assembly_rerun2_manual_one_shot_prompt.md`. This separate Assembly worker reads newly generated Research Git introductions from the new cohort, not the old ones.

## Four architecture preflight answers

1. **Owner of new scope/authorization/retry/write:** GitHub owner and existing Actions as in `config/execution_ownership_contract.json`; an ordinary chat is never the issuer.
2. **Canonical permission:** new narrowly scoped source contract plus explicit `owner_push_no_ui_assembly_replay` policy, **effective only after reviewed source merge and new actual owner first-attempt GitHub push**; the old grant/run ID cannot authorize rerun2.
3. **No control-plane transfer:** old notes are copied by GitHub, not chat; worker only performs separately launched, manifest-bound Assembly. Immutable Git acceptance and strict isolated writer remain GitHub.
4. **No scheduler/queue/retry loop:** exactly one new cohort source push / issuer job; no daily stage, quota, automatic retry, overwrite, recovery, canonical/Deep/production writes or original18 mutation.
