## Предмет

Пользователь сообщает о повторяющейся проблеме: даже если новый директор поначалу отправляет короткую команду работнику, позднее он начинает копировать в сообщение всё содержание длинного задания, которое **уже сохранено в GitHub**. В текущем директорском диалоге это случилось при запуске ЧАТА 2 и ЧАТА 4 после регистрации задач в PR #283: вместо короткой команды со ссылкой на точный WORKER_TASK-файл появились два длинных повторных описания. После замечания пользователя директор признал дубль и привёл короткий пример.

Важное различие: **развёрнутый WORKER_TASK-файл может быть нужен; длинная копируемая команда для запуска работника — нет.** Не путать этот сбой с прежней задачей о непонятном техническом языке (report-only PR #272; предложенная отдельная правка PR #275). Она может быть контекстом, но не ответом на текущую проблему.

## Порядок

1. Полностью прочитай актуальный CHAT_PROTOCOL.md и выполни START gate. Выполни только необходимую ограниченную проверку архитектуры: GitHub — источник задания и правил, worker читает task-файл из main. Никакой проверки производственной системы.
2. Из main проверь точные разделы DIRECTOR_PROTOCOL.md о копируемом запуске, short-prompt template, обязательных repository guard и ротации директорского чата; соответствующие части CHAT_PROTOCOL.md, DIRECTOR_BOOTSTRAP.md, DIRECTOR_HANDOFF_CURRENT.md, верх DIRECTOR_TASK_BOARD.md. При необходимости — действующие файлы конкретных заданий из PR #283 и отдельные отчёты о правилах из PR #272/#275.
3. Установи, какие правила **уже запрещают** длинные промпты, а какие инструкции/образцы или особенности handoff могут неявно стимулировать повторять полное задание внутри копируемого текста. Отдели: (а) доказанное противоречие документации, (б) наблюдаемую ошибку поведения директора, (в) предположения о причинах роста текста. Не утверждай, что имеешь доступ ко всем физическим директорским чатам или скрытому механизму модели.
4. Проверь на одном конкретном сценарии «две параллельные задачи зарегистрированы → директор отправляет два сообщения»: какой **минимальный корректный текст запуска** нужен, чтобы соблюсти протокол, уникальные номера чатов, START gate, repository scope guard и точный путь к WORKER_TASK, без повторения самого задания. Отличи обязательную проверку регистрации/CI от пользовательского копируемого текста.
5. Дай **одно небольшое воспроизводимое решение на будущее**, полезное при смене директорского чата. Если существующее правило полно и достаточно, сообщи, что это проблема исполнения, не добавляй ещё одно правило. Если правило противоречиво или важное требование утоплено в памятке, предложи **замену одной конкретной существующей формулировки**, а не новый перечень обязательных проверок. Учти, что отдельная правка PR #275 пока не принята.
6. До вывода проверь, что предложенный короткий шаблон не нарушает явный repo guard и не теряет обязательный START gate. Поясни, чем подтверждён вывод и где ограничен доступ к прошлым диалогам.
