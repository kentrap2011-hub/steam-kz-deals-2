# GAME-DEALS-MAILING v1.1

Этот документ — человекочитаемое описание `config/mailing_policy.json`. Машинный JSON является каноническим источником правил; при расхождении приоритет у JSON.

## Главные инварианты

- Выпуск — полный ежедневный актуальный срез, не delta.
- Подходящая активная скидка повторяется каждый день, пока действует.
- Уже пройденные игры не исключаются автоматически.
- Платный discovery — только production-feed Steam Kazakhstan из этого репозитория.
- Формат shortlist и шаблон chunks всегда читаются из свежего `data/production/shortlist/index.json`.
- Все chunks обязаны быть прочитаны. Фактический chunk count и число data rows должны совпадать с `chunk_count` и `item_count`.
- QA fail-closed: при неполном/устаревшем/несогласованном feed выпуск не формируется вообще.
- SteamDB используется только после персонального отбора для истории цены Казахстана, не для discovery.
- Wishlist — только контекст, не источник кандидатов и не доказательство вкуса.
- Ценовой ориентир около 500 ₽ мягкий, не жёсткий потолок.
- Нет fixed TOP-N: в выпуск попадают все активные предложения, прошедшие персональный фильтр.
- Рассматриваются base game, remaster/remake, содержательные DLC, passes, полные издания, bundles и Complete the Set.
- Все суммы пользователю показываются только в рублях.

## Защита от пропусков

Каждый кандидат получает внутреннее решение `INCLUDE` либо `EXCLUDE`.

Для `EXCLUDE` обязательна конкретная отрицательная причина. Отсутствие сильного положительного доказательства само по себе не является основанием для исключения. При разумной неопределённости действует `DEFAULT INCLUDE`.

После первого прохода проверяется, что все обработанные кандидаты имеют решение.

Затем проводится false-negative audit только по исключённым позициям с сильными положительными сигналами: `strong_fit`, `strong_niche_fit`, `high_confidence_adjacent`, `exceptional_discount`, `very_high_rating`, `recent_fit`, `substantive_content`, очень большая скидка, исторический/почти исторический минимум, выгодное полное издание или bundle. Если конкретная отрицательная причина недостаточно сильна, позиция переводится в `INCLUDE`.

## Семьи предложений

До дорогих внешних проверок связанные предложения объединяются в одну семью: base / remaster-remake / полные издания / DLC / passes / bundles / Complete the Set. Затем выбирается лучший способ покупки. Слабая версия не должна приводить к потере всей игры.

## Оптимизация времени

1. Policy, профиль, manifest, index и все chunks загружаются ровно один раз.
2. Персональный ledger и группировка offer families строятся одним локальным проходом.
3. Второй проход выполняется только по рискованным `EXCLUDE`.
4. Steam Store проверяется только для `INCLUDE` и реальных borderline-кандидатов.
5. SteamDB проверяется только для окончательных `INCLUDE`.
6. Внешние результаты переиспользуются внутри одной семьи; одинаковые запросы не повторяются.
7. В конце выполняется один контрольный проход по заметным Steam sales.

Скорость нельзя получать урезанием feed, TOP-N или повышением порога персонального фильтра.

## Бесплатные раздачи и «Что скоро»

Они формируются только после успешного основного ingest. Freebies также проходят персональный фильтр минимум `moderate fit`. Горизонт блока «Что скоро» — примерно 60 дней.
