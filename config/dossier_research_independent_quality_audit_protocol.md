# Dossier V2 — обязательный протокол независимого содержательного аудита Research

**Назначение:** READ-ONLY проверка качества уже опубликованных Research notes. Это *операционный evidence gate аудитора*, а не изменение Research/Assembly schemas, технического GitHub writer, очереди, ownership, retry или исполнения. Применять в новой аудиторской сессии до первого вердикта; конкретный audit task задаёт frozen cohort и разрешённые записи.

1. **Независимое исследование до сверки с Research.** Из frozen GitHub manifest установить точные AppID, название, издание/ремастер/DLC и обязательные identity bindings. Затем **самостоятельно найти и содержательно изучить** внешние материалы о каждом конкретном продукте, составив независимый список фактов/вопросов. Только после этого читать утверждения Research и сравнивать. Research `source_log`, готовые URL и GitHub receipts не засчитывать за посещения аудитора. `source_log` в исходной Research schema остаётся необязательным.

2. **Факт доступа и чтения.** Статус `opened/read` разрешён лишь для страницы, реально открытой **и** прочитанной в соответствующей части в *текущей* аудиторской сессии. Поисковая выдача, snippet, preview, URL, сообщение другого worker-а и успешный GitHub receipt — не `opened`. Отдельно отмечать `search_result_only`, `unavailable`/blocked, частичный доступ и нерелевантный фрагмент. Не изображать посещение при отсутствии работающего веб-доступа; честно остановиться с `BLOCKED_EVIDENCE` при невозможности доказательной проверки.

3. **Матрица полноты для каждой игры.** По независимо прочитанным данным проверить: основные механики; доступные режимы (solo/coop и другие существенные); точное издание, DLC, remaster и отличия от оригинала; важные плюсы и минусы в опыте игроков; временную и платформенную принадлежность технических жалоб; пропущенные существенные темы, конкретику, противоречия и неопределённости. Отдельную жалобу не превращать в «частую/массовую» без доказательств распространённости. Различать факты о наличии режима и субъективные оценки качества.

4. **Traceability каждого существенного вывода.** В отчёте указывать для каждой проверяемой Research claim: `claim → точный публичный URL → тип источника (первичный отзыв/официальная страница/обзор/форум/поисковый snippet/недоступный) и реально просмотренный фрагмент с контекстом → CONFIRMED | UNCERTAIN | UNKNOWN → последствие для качества`. Для `CONFIRMED` требуются фактически прочитанная релевантная часть доступного *независимого* внешнего источника и корректная привязка к игре/изданию, платформе и времени, где это существенно. `UNCERTAIN` — фрагмент доступен, но ограничен/спорен/неоднозначен; `UNKNOWN` — независимого подтверждения нет. В сниппете найденное может быть только поисковым указателем/неподтверждённой гипотезой, не `CONFIRMED`. Не выдумывать посещения, цитаты, URL, частоту отзывов или степень уверенности.

5. **Evidence Gate до публикации и оценки.** **По каждой игре отдельно** аудитор перед `QUALITY_GOOD` обязан предъявить реально изученные в своей сессии независимые материалы, достаточные для существенных подтверждённых утверждений, выполнить матрицу полноты и явно раскрыть оставшиеся ограничения. `QUALITY_GOOD` — подтверждённые ключевые claims, разумная полнота и отсутствие выявленных значимых искажений; `QUALITY_WEAK` — достоверно проверенный материал выявляет значимые неточности/пропуски при достаточной самостоятельной проверке; `BLOCKED_EVIDENCE` — недоступен достаточный материал для содержательного суждения, включая отсутствие реального внешнего доступа. Нельзя заменять `BLOCKED_EVIDENCE` на `QUALITY_GOOD` или объявлять `CONFIRMED` на основании единственного Research, URL или GitHub receipt. Если отдельная тема не проверена — `UNKNOWN`, а её влияние на вердикт пояснить. При существенном незакрытом пробеле не присваивать `QUALITY_GOOD`.

**Без формальных квот:** нет минимального числа URL, отзывов, обязательных `source_log` или минут чтения. Значимы качество, конкретность и независимость наблюдений. Сама GitHub CI может проверить формат/публикацию отчёта, но **не может доказать**, что аудитор действительно открыл и прочитал веб-страницу: необходим достоверный след действий в самой аудиторской сессии и проверяемое изложение фактов в отчёте. Если такого следа нет — fail-closed.

**Postmortem:** draft [PR #456](https://github.com/kentrap2011-hub/steam-kz-deals-2/pull/456) сохранил технический report-only результат, но его прежние `4 QUALITY_GOOD / 2 QUALITY_WEAK` **дезавуированы** ввиду отсутствия самостоятельного фактического чтения веб-страниц. Новый аудитор должен повторно независимо проверить шесть игр в отдельном READ-ONLY задании; данный протокол не даёт полномочия запускать Research, Assembly или изменять PR #456.
